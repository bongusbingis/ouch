# Asset pipeline and approval gate

Source files live in `assets/source/{figma,blender,external}`. Production exports live in `assets/{ui,particles,textures,models}`. `manifests/external-assets.json` owns third-party provenance. `manifests/assets.json` owns submitted request history and reconciled Roblox mappings. `manifests/attribution.json` and both credit outputs are derived; do not edit them by hand. Existing Studio assets are not automatically relicensed or claimed as audited.

For each Figma-derived asset, record a `source` object with `figma_file_url`, `figma_node_id`, and `local_export_source`, plus `production_file`. For Blender assets, record `source_blend`, `export_path`, and `review_sheet`. The upload result adds `asset_id`, `revision`, and `moderation_state`. Save sources and evidence before submitting.

Search symbols in this order: canonical Figma/project component, approved local asset, Iconify, local Kenney CC0 library, Game-icons licensed assets, custom Figma artwork, then generated artwork only if existing sources are inadequate. `iconctl search` reports these groups; Figma MCP performs the live canonical inspection. Prefer Material Symbols Rounded and Phosphor Bold/Fill. `iconctl acquire collection:icon --output assets/ui/name.png` preserves the original SVG and rasterizes explicitly with the native resvg wheel. SVG output remains available for Figma. Do not silently alter existing production bytes.

The Iconify collection metadata supplies author, collection, source identifier, source URL, SPDX/license URL, and full notice text. The manifest records modifications, source/output paths, and both hashes. See [Iconify search](https://iconify.design/docs/api/search.html) and [collection metadata](https://iconify.design/docs/api/collection.html). Use `--license-text` for a locally reviewed upstream license if its URL returns HTML. Never treat an HTML webpage as a license text.

Automatic licenses: CC0-1.0, MIT, ISC, Apache-2.0, CC-BY-3.0, CC-BY-4.0. Preserve copyright/license notices for permissive licenses too. CC-BY-SA, MPL, and custom licenses stop for manual review; ambiguous, unknown, unpermitted proprietary, noncommercial, and no-derivatives licenses are blocked by the conservative policy. The current tool has no manual-review bypass; resolve those cases before acquisition. Original project-owned assets require explicit author/provider/source and Project-Owned provenance. Do not falsely label third-party assets as project-owned.

Keep Kenney pack source URL, CC0 license text/path, local directory, and indexed assets in `asset-library/kenney/index.json`. Raw packs belong under ignored `asset-library/kenney/raw/`; vendor only selected production assets and their provenance. No bulk packs are downloaded by bootstrap.

Use `iconctl contact-sheet <candidate PNGs> --reference <current UI PNG> --output .review/icons.png` and one Gemini review to rank a group. Codex makes the final choice and registers the canonical Figma component. `generate_credits.py` deterministically writes THIRD_PARTY_NOTICES.md, manifests/attribution.json, and generated/ThirdPartyCredits.luau. The Luau module is an export artifact, not yet wired to an in-game credits screen; choosing that UI seam is a separate gameplay/UI task.

## Gate installation and scope

Run `.\.agent-venv\Scripts\python.exe tools\install_asset_gate.py`. It installs a separate Python 3.12 virtualenv, Tkinter application, and launcher under `%LOCALAPPDATA%\RobloxAssetGate`, and adds `bin` to the current user's PATH. Open a new PowerShell after installation. No administrator, daemon, server, Docker, Electron, browser automation, Roblox cookies, or Blender MCP is used.

The repository carries reviewable installer source. `gate_runtime.py` refuses credential lookup and production network operations unless loaded from the fixed installed location. The launcher uses Python isolated mode; installed modules do not import repository code. Reinstall deliberately after reviewing gate-source changes; active gate instances hold a Windows file lock so installation cannot race an approval/upload. Installation preserves durable state.

Only the installed gate retrieves `roblox-asset-gate-opencloud` / `api-key`. Project assetctl prepares requests and invokes the installed app. Doctor asks that app for credential presence; it never retrieves the Roblox key. Keys are never passed in environment variables, command arguments, request JSON, manifests, or result files.

**Security boundary limitation:** under the required same-user, no-admin architecture, arbitrary code running as that Windows user can read the same Credential Manager entries, modify installed Python files, or synthesize UI input. Tkinter cannot prove a click came from a human. These tools technically enforce the normal workflow and expose no unattended approval command, but cannot provide the absolute guarantee against a malicious/unrestricted same-user agent. That requires a separately protected identity/device or trusted OS-mediated approval service, which is outside this bootstrap's specified architecture. Agents must never automate production approval or access the gate credential directly.

## Request lifecycle

1. Validate with `validate_assets.py --file ... --asset-type ...`. Supported formats/limits are centralized in `asset_policy.py`, copied into the gate. The initial gate deliberately supports images and self-contained FBX/GLB models; audio, animation, loose glTF, video, and Studio place files fail closed. Roblox's API supports additional types; see the [official usage guide](https://create.roblox.com/docs/cloud/guides/usage-assets).
2. `assetctl submit` writes a durable PREPARED proposal under `.asset-requests`, then the installed gate reads it, checks the proposed hash, freezes exact bytes and model previews, independently revalidates, and commits WAITING_FOR_APPROVAL to SQLite before showing the GUI.
3. Images show a checkerboard preview and native dimensions. Models require front, rear, left, right, top, perspective, wireframe, material, and Studio image paths plus statistics and a saved `.blend` path in `--model-evidence` JSON. These are review evidence, not a claim that this gate parses all geometry or proves the images depict the model.
4. The GUI displays filename, SHA-256, size/dimensions or declared model statistics, type, creator, name, description, update target, provenance, license, attribution, validation results, and the human compliance statement. Metadata is read-only. Closing the window preserves pending approval. DENY never retrieves credentials or writes to Roblox.
5. Only APPROVE & UPLOAD in a production GUI enters the upload path. The in-memory bytes rendered/verified are the bytes transmitted. Binding includes hash, type, creator, name, description, update asset ID, provenance, evidence hashes, and demo mode. Changed frozen bytes or metadata invalidate approval. A changed source requires a new request to upload that revision; it cannot silently change the existing frozen request.
6. Persist APPROVED, then UPLOAD_STARTING before the network call. A response and operation ID are committed together immediately. No automatic create/update retry occurs, including on HTTP errors. Known operations are polled through `resume`; pending moderation never becomes production-ready. Only an explicit approved moderation result with an asset ID becomes COMPLETE.
7. Non-secret results go to external `results/` and project `.asset-inbox`. Reconciliation checks request identity/hash/path/demo mode, applies newer sequence numbers once, refuses to map changed production bytes, and atomically replaces the manifest under a Windows file lock. Denied/failed results remain in request history. The inbox is a trusted local handoff, not a cryptographically authenticated cross-user channel.

`--target-asset-id` requests an FBX Model content update; the target is part of the displayed approval binding. Current upstream docs limit content updates to FBX. Production creates use the Open Cloud Assets API; no Creator Dashboard automation. No bootstrap smoke test sends a real Roblox write.

## Recovery semantics

SQLite uses WAL and synchronous FULL, with frozen bytes fsynced before the request is committed. Result file writes use flush/fsync and atomic replacement. External directories are `frozen`, `previews`, `results`, `logs`; no state depends on a shell variable or a running daemon. A process-wide Windows lock prevents concurrent gate writers and is released by Windows after a crash.

An interrupted APPROVED state returns to WAITING_FOR_APPROVAL. UPLOAD_STARTING without a durable operation becomes RECOVERY_REQUIRED. Never resubmit it automatically: an asset may exist remotely already. A known operation is retained and only polled. Repeated CLI invocations replay durable result handoffs if the project was temporarily unavailable. Unknown moderation remains pending; verify through Roblox if polling does not expose a final state.

Back up the complete external gate directory and project sources. For live SQLite backups use SQLite's backup API; copying only the database while it is open can omit its WAL. No application can promise storage-device survival after physical disk failure.
